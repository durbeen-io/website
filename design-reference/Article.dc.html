How to judge a GitHub repo before you trust it

Stars are not a safety check. A ten-minute routine for anything you plan to install, run or build on.

Most people decide whether to trust a repository in about three seconds: they look at the star count. It is the wrong signal. Stars measure attention, not quality, and certainly not safety.

Why stars mislead

A project can collect thousands of stars in a week from one viral post. That tells you people were curious. It tells you nothing about who maintains it, what it installs, or whether it still works.

Stars measure attention. You need to measure intent: what the code actually does on your machine.

The ten-minute check

Before installing anything, answer five questions:

  1. Licence. Is there one, and does it allow what you plan to do?
  2. Activity. When was the last commit? Are issues answered?
  3. Owner. Is this the original project, or a copy?
  4. Install path. What runs during installation, and where does it write?
  5. Network. Does it call out to anything you did not expect?

Read the install script

Search the code for anything that downloads, executes or deletes. A two-line search catches most surprises:

# find network calls and shell execution
grep -rnE "curl|wget|fetch\(|requests\." .
grep -rnE "subprocess|exec\(|eval\(" .

Watch for look-alikes

Popular projects attract copies with near-identical names. Always install from the owner named in the official documentation, never from a link in a comment or a search result.

VERDICT■ USE THE CHECKLIST
Ten minutes of checking is cheap. Cleaning up a compromised laptop is not. Save this routine and run it every time.
